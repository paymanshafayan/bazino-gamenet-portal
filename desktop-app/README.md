# BAZINO PRO Desktop

نسخه‌ی دسکتاپ مستقل نرم‌افزار مدیریت گیم‌نت — بک‌اند Node.js واقعی + دیتابیس SQLite محلی، همه داخل یک اپ نصبی، با قابلیت اتصال به سرور سایت برای دریافت/ارسال داده (مثل رزروهای آنلاین).

> ⚠️ **این کل پوشه در یک sandbox بدون Electron، بدون npm/node واقعی قابل‌اجرا، و بدون اینترنت نوشته شده.** فقط syntax-check با esbuild انجام شده — **هیچ‌کدوم از مراحل زیر واقعاً اجرا/تست نشدن.** قبل از تحویل به کاربر نهایی، حتماً روی یک ماشین واقعی (ویندوز/مک/لینوکس) کامل تست کنید.

---

## این چیه، دقیقاً؟

یک پنجره‌ی Electron که:
1. همون بک‌اند واقعی سایت (`server.ts` از ریشه‌ی پروژه، build شده به `server.cjs`) رو **داخل خودش** (in-process، بدون نیاز به `node` جدا) اجرا می‌کنه.
2. با **SQLite محلی** کار می‌کنه (پیش‌فرض همون بک‌اند، بدون نیاز به دیتابیس جدا) — دیتای گیم‌نت کاملاً روی همون کامپیوتر ذخیره می‌شه، آفلاین کار می‌کنه.
3. پنجره‌اش مستقیم صفحه‌ی Management App (`/management-app`) از همون سرور محلی رو نشون می‌ده.
4. از داخل خود Management App (تب «Web Sync» → «تنظیمات»)، می‌شه آدرس سرور **آنلاین سایت واقعی** + یک API Key رو وارد کرد تا این نسخه‌ی محلی بتونه رزروهای آنلاین رو از سایت بگیره و وضعیت ایستگاه‌ها رو بهش گزارش بده (کد کامل در `server.ts` مسیرهای `/api/sync/*`، و کلاینتش در `Management App/Bazino/src/utils/syncClient.ts` + `components/WebSyncModal.tsx`).

## پیش‌نیازها

- Node.js نصب‌شده روی همون ماشینی که build می‌گیرید (نسخه ۲۰+ توصیه می‌شه).
- ریشه‌ی پروژه از قبل با موفقیت `npm install && npm run build` شده باشه (این پوشه خروجی‌های اون build رو کپی می‌کنه، خودش نمی‌سازتش).
- برای build واقعی نصاب: سیستم‌عامل مقصد باید همون سیستم‌عاملی باشه که روش build می‌گیرید (به بخش «محدودیت مهم: ماژول‌های native» پایین‌تر مراجعه کنید).

## مراحل تست محلی (قبل از ساخت نصاب)

```bash
# ۱. از ریشه‌ی پروژه (نه این پوشه):
cd ../..
npm install
npm run build

# ۲. برگردید به این پوشه، پکیج‌های Electron رو نصب کنید:
cd desktop-app
npm install

# ۳. bundle بک‌اند رو آماده کنید (سایت build شده + Management App build شده +
#    node_modules پروداکشن را کپی و برای Electron rebuild می‌کنه — به اینترنت نیاز داره):
npm run prepare-server-bundle

# ۴. اجرای آزمایشی:
npm start
```
اگه همه‌چیز درست باشه، یک پنجره باز می‌شه و صفحه‌ی Management App رو نشون می‌ده — دقیقاً مثل وقتی که از مرورگر به `http://localhost:3000/management-app` می‌رید، ولی حالا بک‌اندش کاملاً محلیه.

## ساخت نصاب واقعی (installer)

```bash
npm run dist:win     # روی ویندوز اجرا کنید
npm run dist:mac     # روی مک اجرا کنید
npm run dist:linux   # روی لینوکس اجرا کنید
```
خروجی در پوشه‌ی `release/` قرار می‌گیره (فایل `.exe`/`.dmg`/`.AppImage`).

### ⚠️ محدودیت مهم: ماژول‌های native (به‌خصوص `better-sqlite3`)
بک‌اند از `better-sqlite3` استفاده می‌کنه که یک ماژول native (کامپایل‌شده مخصوص هر سیستم‌عامل/معماری) هست. Electron هم نسخه‌ی Node.js داخلی خودش رو داره که ABI متفاوتی از Node.js سیستم شما داره. اسکریپت `prepare-server-bundle` خودش `@electron/rebuild` رو اجرا می‌کنه تا این ماژول رو مخصوص Electron کامپایل کنه — **ولی این کامپایل فقط برای سیستم‌عامل/معماری‌ای که الان روش هستید کار می‌کنه.**

یعنی:
- برای نصاب **ویندوز واقعی**، باید `npm run prepare-server-bundle && npm run dist:win` رو **روی خود ویندوز** اجرا کنید (نه از لینوکس/مک با cross-compile).
- همین‌طور برای مک و لینوکس.
- اگه می‌خواید هر سه رو خودکار و هم‌زمان بسازید، **همین کار الان انجام شده**:
  `.github/workflows/desktop-installers.yml` با matrix سه‌تا runner (`windows-latest`,
  `macos-latest`, `ubuntu-latest`) هر سه نصاب رو می‌سازه و به یک GitHub Release می‌چسبونه.
  دو راه اجرا داره: دستی (Run workflow) و خودکار با هر push که چیزی زیر `desktop-app/` عوض کنه.

## چطور کار می‌کنه (برای دیباگ)

- `main.js`: پروسه‌ی اصلی Electron. `dataDir` رو (پوشه‌ی داده‌ی کاربر، مثلاً `%APPDATA%/BAZINO PRO` در ویندوز) به‌عنوان `process.cwd()` ست می‌کنه (اونجاست که `install-config.json` و فایل SQLite ذخیره می‌شن — این پوشه با آپدیت/حذف‌نصب اپ از بین نمی‌ره)، و متغیر `BAZINO_STATIC_ROOT` رو به مسیر واقعی فایل‌های build شده ست می‌کنه (چون این دو مسیر متفاوتن — `server.ts` این متغیر رو می‌خونه، پیش‌فرضش `process.cwd()`ه که برای deploy عادی هنوز درست کار می‌کنه).
- یک `JWT_SECRET` تصادفی در اولین اجرا تولید و در `dataDir/.jwt-secret` ذخیره می‌شه (به‌جای مقدار پیش‌فرض ناامن کد).
- `scripts/prepare-server-bundle.js`: خروجی build ریشه‌ی پروژه رو کپی می‌کنه. برای وابستگی‌ها
  **اول `node_modules` ریشه رو کپی می‌کنه** (آفلاین و از قبل کامپایل‌شده) و فقط اگه ناقص بود
  سراغ `npm install` می‌ره؛ در انتها هم واقعاً `better-sqlite3` رو از داخل bundle load می‌کنه
  تا مطمئن بشه اپ موقع اجرا بالا میاد. این پوشه (`server-bundle/`) در `.gitignore` هست.
- `scripts/run-headless-desktop.cjs`: همون مسیر راه‌اندازی `main.js` رو **بدون Electron** اجرا
  می‌کنه (chdir به پوشه‌ی داده، `BAZINO_STATIC_ROOT`، تولید JWT، و require کردن `server.cjs`).
  برای تست سریع بک‌اند دسکتاپ و گرفتن اسکرین‌شات از UI با یک مرورگر معمولی:

  ```bash
  node scripts/run-headless-desktop.cjs      # سپس http://localhost:3100/management-app
  ```

## عیب‌یابی سریع

| مشکل | احتمال علت |
|---|---|
| پنجره باز می‌شه ولی صفحه خالیه/ERR_CONNECTION_REFUSED | سرور محلی هنوز کامل بالا نیومده بود؛ `setTimeout` در `main.js` رو زیاد کنید، یا (بهتر) به یک poll واقعی تبدیلش کنید |
| کرش موقع باز شدن، لاگ چیزی شبیه `NODE_MODULE_VERSION mismatch` | `@electron/rebuild` اجرا نشده یا برای سیستم‌عامل/Electron نسخه‌ی دیگه‌ای اجرا شده — `prepare-server-bundle` رو دوباره روی همون ماشین اجرا کنید |
| نصاب برای ویندوز از لینوکس/مک ساخته شده ولی روی ویندوز کار نمی‌کنه | محدودیت native module بالا — باید روی خود ویندوز build بگیرید |
