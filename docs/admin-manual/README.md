# راهنمای جامع تصویری پنل مدیریت بازینو

نسخه ۱.۱ — ۱۵ سپتامبر ۲۰۲۶ / ۲۴ شهریور ۱۴۰۵
مبنای کد: `a9c2c21010146b2fe51df323373ec279b88f5ac1` — نسخه بدون هدر بنفش اضافی که کاربر تأیید کرد؛ به‌اضافه اتصال آیکون راهنما به سند جدید.

## خروجی آماده استفاده

- **وب:** `/admin-manual/index.html` — راست‌به‌چپ، جست‌وجوی عنوان و متن، فهرست دسته‌بندی‌شده، بزرگ‌نمایی تصاویر، کار با صفحه‌کلید و نمای موبایل.
- **HTML آفلاین:** `public/admin-manual/bazino-admin-manual.html` — یک فایل مستقل؛ همه تصاویر و فونت‌ها داخل فایل‌اند. برای مطالعه، جستجو و بزرگ‌نمایی اینترنت لازم نیست. دکمه PDF به فایل هم‌نام کناری اشاره می‌کند؛ هر دو را کنار هم نگه دارید.
- **PDF:** `public/admin-manual/bazino-admin-manual.pdf` — ۵۶ صفحه A4، متن فارسی قابل انتخاب/جستجو، فهرست پیونددار، نشانک‌ها و شماره صفحه.
- **پوشش:** ۳۳ فصل، ۴۳ تصویر آموزشی، ۲۴ ورودی مدیریتی در منو. ۲۳ مسیر مستقیم و جارویس از منوی «فنی».

آیکون علامت سؤال در نوار بالایی ۵۰ پیکسلی پنل، نسخه وب را در زبانه جدید باز می‌کند. راهنماهای قدیمی زمینه‌ای حذف نشده‌اند؛ این سند مرجع جدید است. سند استاتیک عمومی است، حاوی اطلاعات آموزشی است و داده زنده یا دسترسی مدیریتی نمی‌دهد.

## دامنه و اعتبار محتوا

این سند از **بررسی کد همین پروژه و اجرای محلی آن** تهیه شده؛ نه از توضیح عمومی یک پنل فرضی. فایل `content.json` منبع نگارش است: هدف هر فصل، مسیر، مراحل، معنی فیلدها، تصاویر، نکته‌ها و هشدارها.

تصاویر، اسکرین‌شات واقعی مرورگر با داده ساختگی‌اند؛ لوگو/پنل با هوش مصنوعی بازسازی نشده است. وزیرمتن محلی برای خوانایی تزریق شد، تصاویر بریده شدند و دو تصویر با قاب/شماره آموزشی نشانه‌گذاری شدند. این تغییرها قابلیت یا نتیجه عملیاتی را جعل نمی‌کنند. تصاویر فرم‌ها لزوماً همه ارتفاع فرم یا فهرست را نشان نمی‌دهند.

### بازبینی تصویری نسخه ۱.۱

تمام ۴۳ تصویر مرجع پس از تأیید کاربر دوباره گرفته شدند؛ تصاویر استفاده‌نشده نسخه قبلی نیز از پوشه انتشار حذف شدند. نمای کلی از خود `#admin-wrap` گرفته شده، نه کل صفحه با حاشیه قالب سایت. تصویر ورود داخل کادر فرم بریده شده و تصویر حقوقی فقط ویرایشگر مربوط را نشان می‌دهد. رنگ‌های واقعی فرم‌های توکار دست‌کاری نشده‌اند.

`image-refresh.json` زمان و هش تصاویر خام/منتشرشده را ثبت می‌کند. دو تصویر شماره‌گذاری دارند. URL تصاویر وب شامل هش محتواست تا کش مرورگر عکس قدیمی نشان ندهد. HTML مستقل و PDF از همین تصاویر بازسازی شده‌اند.

### آنچه انجام شد

- اجرای نصب SQLite جداگانه و داده نمونه، ثبت مشتری و تیکت آموزشی.
- بازدید از ۲۳ بخش مسیرپذیر و جارویس از منو؛ بازکردن زیرتب‌ها، فرم‌ها و پنجره‌های مهم.
- ثبت یک سیستم آموزشی و ذخیره یک پیش‌نویس پست در پایگاه داده محلی.
- بررسی فرم پرداخت دستی POS، نقدکردن، کوپن، ساعات ویژه، ثبت‌نام مسابقه، پاسخ تیکت و کمپین تا **پیش از تأیید نهایی حساس**.
- عکس ناموفق تلگرام/عدم اتصال، همان‌طور که واقعاً دیده شد، همراه توضیح محدودیت نگه داشته شد.

### آنچه انجام نشد

پرداخت/بازپرداخت بانکی، تحویل پول، انتشار شبکه اجتماعی، پیامک/پیام‌رسان خارجی، بارگذاری APK/قالب، تأیید مالی کمپین، مصرف اعتبار مدل هوش مصنوعی یا اجرای مهارت نوشتنی جارویس آزموده نشده‌اند. رفتارهای این قسمت‌ها از رابط و کد خوانده شده و در راهنما با احتیاط توضیح داده شده‌اند. قطع درخواست‌های خارجی **مرورگر** جایگزین ایزوله‌سازی سرور نیست؛ محیط آموزشی باید فاقد کلید سرویس و داده واقعی باشد.

### محدودیت‌های نسخه بررسی‌شده

- شناسه `jarvis` در فهرست مسیرهای مستقیم/نوع `AdminSection` ثبت نشده؛ ورود از منو ممکن است، لینک مستقیم قابل اتکا نیست.
- تب تلگرام بدون درگاه/کلید، خطای `Cannot read properties of null (reading 'items')` نشان داد؛ تصویر آن اثبات اتصال موفق نیست.
- کارت‌های برخی آمار داشبورد در داده آموزشی خط تیره/بدون عدد معتبر بودند.
- تفاوت استودیوی ساده «محتوا»، استودیوی V4 در «همکاری» و فرم مستقیم بلاگ صریحاً توضیح داده شده است.
- واحد مبالغ باید از خود فرم خوانده شود؛ در فرم‌های عملیاتی TL است. POS این نسخه ثبت دستی رسید است، نه فرمان به دستگاه کارت‌خوان.

## بازسازی HTML و PDF از منابع موجود

از ریشه مخزن:

```bash
node scripts/build-admin-manual.mjs
```

این دستور بدون شبکه از `content.json`، تصاویر و فونت‌های موجود، وب و HTML مستقل را بازسازی می‌کند. اگر تصویری جا افتاده باشد شکست می‌خورد.

برای آزمون مرورگر و PDF، وابستگی‌های مرورگر مطابق `BROWSER_TESTING_SANDBOX.md` نصب باشند. `tests/e2e-browser/lib.mjs` از Chromium موجود استفاده می‌کند؛ می‌توانید مسیر آن را با `CHROMIUM_EXECUTABLE_PATH` بدهید.

در یک ترمینال/فرایند پایدار، فقط سند را سرو کنید (برای PDF به دیتابیس یا ورود مدیر نیاز نیست):

```bash
python3 -m http.server 3002 --bind 0.0.0.0 --directory public
```

سپس:

```bash
MANUAL_BASE=http://127.0.0.1:3002 node tests/e2e-browser/render-admin-manual.mjs
```

این تست، جستجو، پاک‌کردن جستجو، حالت بدون نتیجه، پیوندها، تصاویر، بزرگ‌نمایی و Escape، موبایل و HTML مستقل بدون شبکه را بررسی می‌کند؛ PDF را نیز می‌سازد. تصاویر QA در `MANUAL_RUNTIME` یا پوشه موقت سیستم ذخیره می‌شوند، نه در گیت. فایل‌های `validation.json` و `pdf-validation.json` نتیجه ارزیابی نسخه تحویلی‌اند. برای بررسی ساختار PDF با وابستگی اختیاری PyMuPDF: `python scripts/check-admin-manual-pdf.py`. این بررسی تعداد صفحه، پیوندهای داخلی، متن فارسی و خروج متن از کادر را کنترل می‌کند؛ جای بازبینی بصری را نمی‌گیرد.

## تصویربرداری مجدد — فقط محیط دورریختنی

برای بازسازی خروجی موجود نیازی به اجرای این بخش نیست. عکس‌برداری مجدد، محیط آماده با داده آموزشی مشابه لازم دارد؛ تغییر داده نمونه یا CSS می‌تواند انتخابگرها و قاب‌بندی را تغییر دهد. هر تصویر جدید باید دستی بازبینی شود.

1. یک پوشه **جدید و خارج مخزن** برای داده آموزشی بسازید. سرور را با `BAZINO_DATA_DIR` همان پوشه و `JWT_SECRET` تصادفی اجرا کنید. تنظیمات Mongo/درگاه/کلیدهای نصب واقعی نباید در محیط آن وجود داشته باشند. به نصب واقعی یا تونل آن وصل نشوید.
2. `MANUAL_BASE` را روی همان سرور localhost و `MANUAL_RUNTIME` را روی پوشه آموزشی بیرون مخزن قرار دهید.
3. فقط برای نصب خالی و یک بار:

```bash
export MANUAL_BASE=http://127.0.0.1:3000
export MANUAL_RUNTIME=/absolute/path/outside/repo/training-runtime
MANUAL_TRAINING_SETUP=YES_CREATE_TRAINING_DATA \
  node tests/e2e-browser/prepare-admin-manual.mjs
```

اسکریپت نصب قبلی را رد می‌کند، رمز تصادفی می‌سازد و نشست را با دسترسی `0600` ذخیره می‌کند؛ هیچ رمز یا توکنی چاپ نمی‌شود. خودِ راهنمای تحویلی با همین توالی API در نصب محلی تهیه شد؛ اسکریپت تجمیع‌شده برای نصب آموزشی تازه اجرا و آزمایش شد؛ روی دیتابیس نصب‌شده اجرا نشده است.

4. ضبط صفحات و جزئیات:

```bash
node tests/e2e-browser/capture-admin-manual.mjs
# فقط در دیتابیس دورریختنی: ثبت سیستم و ذخیره پیش‌نویس آموزشی
MANUAL_ALLOW_TRAINING_WRITES=1 node tests/e2e-browser/capture-admin-manual-details.mjs
# یک بار، پس از تصاویر خام جدید
node scripts/annotate-admin-manual.mjs
node scripts/build-admin-manual.mjs
node tests/e2e-browser/render-admin-manual.mjs
```

بدون `MANUAL_ALLOW_TRAINING_WRITES=1` فرم‌های حساس ثبت نمی‌شوند و تصاویر نتیجه ثبت سیستم/پیش‌نویس تازه تولید نمی‌شوند. اجرای دوباره با این گزینه ممکن است رکورد آموزشی تکراری بسازد؛ این اسکریپت جایگزین migration یا seed تولید نیست. در بازبینی ۱.۱ ضبط پایه ۲۳ بخش و ضبط جزئیات دوباره اجرا شدند. ورود در اجرای نخست دچار تأخیر شد؛ با مرورگر مستقل دوباره ضبط شد. تصویر نتیجه ثبت سیستم نیز بدون اعلان موقت دوباره گرفته شد. نتیجه نهایی همه گروه‌های ضبط موفق بود. برای تکرار فقط یک گروه می‌توان `MANUAL_ONLY=login` داد؛ `MANUAL_ONLY=systems-saved-review` فقط نتیجه سیستم موجود را عکس می‌گیرد و رکورد تازه نمی‌سازد.

برای ضبط مرحله‌ای، `MANUAL_OUTPUT` را روی پوشه موقت تصاویر بگذارید و پس از بازبینی فقط فایل‌های مرجع JSON را به assets منتقل کنید. فایل‌های جدید را بدون حذف هم‌زمان/ایجاد دوباره جایگزین کنید؛ در صورت کش قدیمی فهرست public در Vite، سرور توسعه را راه‌اندازی مجدد کنید.

پس از ضبط، خروجی `capture-results.json` و `details-results.json` در runtime، همه تصاویر و فیلدهای کلید/رمز را بررسی کنید. اگر تصویری کلید/اطلاعات واقعی نشان می‌دهد، آن را منتشر نکنید. نشست، پایگاه داده و خروجی‌های خام runtime نباید وارد گیت شوند.

## نتیجه کنترل کیفیت این نسخه

- بازبینی تصاویر: ۴۳ از ۴۳ دوباره ضبط و بازبینی شدند؛ فایل PNG قدیمی یا استفاده‌نشده در assets نیست. `node scripts/verify-admin-manual-assets.mjs` هش منابع، URLهای وب و تصاویر جاسازی‌شده آفلاین را کنترل می‌کند.
- ۱۵ کنترل مرورگر سند: موفق؛ ۳۳ فصل و ۴۳ تصویر، بدون تصویر/پیوند داخلی مفقود.
- HTML مستقل: تصاویر، فونت و جستجو بدون درخواست شبکه کار کردند.
- نمای موبایل ۳۹۰ پیکسل: بدون سرریز افقی؛ فهرست قابل بازکردن.
- PDF: ۵۶ صفحه؛ متن فارسی قابل استخراج، بدون صفحه تقریباً خالی یا متن خارج از کادر صفحه. جلد، فهرست و نمونه صفحات متن/تصویر بازبینی بصری شدند.
- `npx vite build`: موفق (ساخت فرانت‌اند، نه بسته دسکتاپ یا باندل کامل سرور).
- `npm run lint`: ناموفق به‌دلیل خطاهای از قبل موجود و خارج از دامنه این بازبینی: importهای گمشده `awayPolicy`/`monitor`، ناسازگاری نوع/مسیر `jarvis`، و ویژگی JSX تکراری در `AdminKeysCenter`. این اشکالات در این درخواست مستندسازی تغییر داده نشدند.

## نگهداری و مجوز

پس از تغییر فرم، واحد مالی، اعتبارسنجی یا گردش‌کار، هم متن JSON و هم تصویر فصل را بازبینی کنید؛ صرف بازسازی HTML، صحت متن قدیمی را تضمین نمی‌کند. تاریخ نسخه در سازنده و متن مقدمه صریح است و باید همراه بازبینی بعدی به‌روز شود.

فونت وزیرمتن تحت SIL Open Font License 1.1 استفاده شده؛ متن مجوز و اعلام حق مؤلف در `public/admin-manual/assets/OFL.txt` همراه خروجی است. اسکرین‌شات‌ها مربوط به همین پروژه و داده آموزشی‌اند.
