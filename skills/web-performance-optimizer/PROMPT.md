# پرامپت آماده: بهینه‌سازی عملکرد وب

پرامپت زیر را به همراه URL، گزارش عملکرد یا ریپوی هدف استفاده کنید.

```text
از مهارت `web-performance-optimizer` استفاده کن تا این پروژه وب را به‌صورت عملی ممیزی و بهینه‌سازی کنی.

ورودی‌ها:
- URL/محیط هدف: [URL یا preview را وارد کن]
- گزارش موجود: [Lighthouse / GTmetrix / PageSpeed / HAR را وارد یا attach کن]
- هدف محصول و محدودیت‌ها: [مثلاً حفظ ظاهر، پشتیبانی مرورگرهای قدیمی، عدم حذف analytics ضروری]
- فرمان‌های اعتبارسنجی پروژه: [در صورت وجود]

انتظار دارم:
1. ابتدا محیط deploy، framework، مسیر build و معتبر بودن asset hashهای گزارش را تشخیص بدهی.
2. یافته‌ها را بر اساس اثر، اطمینان و ریسک اولویت‌بندی کنی.
3. موارد LCP، CLS، Main Thread/TBT/INP، unused JavaScript، تصاویر، فونت‌ها، cache policy، critical request chain و third-party code را بررسی کنی.
4. فقط تغییرات قابل‌اثبات و کم‌ریسک را در کد/config پیاده‌سازی کنی؛ قابلیت‌ها، امنیت، دسترس‌پذیری و طراحی را خراب نکن.
5. کدهای route/modal/admin/editor/ZIP parser و داده‌های پایین صفحه را در صورت نیاز lazy/defer کنی، اما تصویر و محتوای واقعی LCP را lazy نکنی.
6. برای static hosting و server hosting، header/cache/CSP را در مسیر deploy واقعی بررسی و اعمال کنی.
7. برای هر regression مهم، یک test یا performance guard اضافه کنی.
8. lint، test، build و git diff --check را اجرا کنی. اگر انجام هرکدام ممکن نبود، علت دقیق را گزارش بدهی.
9. در پایان، یک گزارش فارسی شامل تغییرات، دلیل، قبل/بعد اندازه bundle در صورت دسترس، اعتبارسنجی‌های اجراشده، محدودیت‌های خارج از کنترل و مراحل deploy/re-test ارائه کنی.

از تغییرات صرفاً ظاهری یا بهینه‌سازی‌های بدون شواهد خودداری کن. اگر گزارش به deploy قدیمی اشاره می‌کند، آن را واضح بیان کن و نتیجه را به‌عنوان بهبود deployنشده جا نزن.
```

## نمونه استفاده کوتاه

```text
از مهارت web-performance-optimizer استفاده کن. گزارش GTmetrix پیوست شده و URL production برابر https://example.com است. هدف: کاهش LCP زیر 2.5 ثانیه، حذف CLS ناشی از فونت و کاهش JavaScript اولیه بدون تغییر تجربه صفحه اصلی.
```
